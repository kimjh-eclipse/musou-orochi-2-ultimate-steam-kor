# 아카이브·압축·문자열

이 문서는 Steam판 WO3U DE에서 확인한 구조를 설명합니다. PC판 아카이브는 **리틀 엔디언**입니다. PS3판(빅 엔디언)과 필드 배치는 비슷하지만 압축 래퍼와 파일 구성이 다릅니다.

## 파일 구성

설치 폴더에는 공통 데이터 4개와 언어별 데이터 4개가 있습니다.

| 파일 | 내용 |
|---|---|
| `LINKIDX_000~003.BIN` / `LINKFILE_000~003.BIN` | 공통 리소스(모델·텍스처·음성 등) |
| `LINKIDX_JPN/ENG/CHS/CHT.BIN` / `LINKFILE_*.BIN` | 언어별 리소스(텍스트·폰트·글자가 든 이미지) |

8개 IDX는 모두 **36,200개 레코드**(1,158,400바이트)로 같은 ID 공간을 공유합니다. 각 파트는 자기가 가진 ID만 채우고 나머지는 0입니다. 네 언어 파트는 같은 **2,022개 ID**를 가지므로, 일본어 파트의 항목 구조를 틀로 삼아 중국어 간체 파트의 같은 ID를 교체할 수 있습니다.

## LINKIDX 레코드

| 레코드 내 위치 | 형식 | 의미 |
|---|---|---|
| `+0x00` | u64 LE | LINKFILE 내 시작 오프셋 |
| `+0x08` | u64 LE | 압축 해제 후 크기 |
| `+0x10` | u64 LE | 저장된 크기 |
| `+0x18` | u64 LE | 압축 플래그(0이 아니면 블록 압축) |

원본 LINKFILE에서 항목은 **ID 순서로, 0x100 경계에 맞춰** 놓여 있고 사이는 0으로 채워져 있습니다. 한국어 빌드도 같은 규칙으로 파트를 다시 씁니다. 교체한 항목의 크기가 바뀌므로 뒤의 항목 오프셋이 모두 달라지고, 파일 전체 길이도 원본과 다릅니다(원본 720,145,664 → 완성본 692,645,888바이트). 그래서 PS3판과 같은 제자리 구간 패치를 쓰지 않고 [재구성 방식](patcher.md)을 씁니다.

## 블록 압축

압축 항목은 다음 래퍼입니다.

| 위치 | 형식 | 내용 |
|---|---|---|
| `0x00` | u32 | 블록 크기(압축 전, 보통 `0x10000`) |
| `0x04` | u32 | 블록 수 N |
| `0x08` | u32 | 전체 압축 해제 크기 |
| `0x0C` | u32 × N | 블록별 레코드 크기 |
| `align(12+4N, 0x80)` | 반복 | u32 zlib 길이 + zlib 스트림, 레코드 끝을 0x80 경계로 |

다시 압축할 때는 원래 항목의 블록 크기를 그대로 쓰고 zlib level 9로 압축합니다. 빌드는 모든 교체 항목에 대해 `decompress(compress(x)) == x`를 확인합니다.

## 텍스트 컨테이너

텍스트 리소스는 세 종류의 노드가 중첩된 형태입니다. 파서(`tools/kt_text.py`)는 경계 검사를 통과하는 노드만 인식합니다.

**LX 문자열 표** — 서명 `XL`(리틀 엔디언 표기)

| 위치 | 형식 | 내용 |
|---|---|---|
| `+0x00` | 2 B | `XL` |
| `+0x02` | u16 | 버전 `0x13` 또는 `0x14` |
| `+0x08` | u16 | 레코드 수 |
| `+0x0A` | u16 | 레코드 폭(4 또는 8 이상) |
| `+0x0C` | u32 | 레코드 표 시작(노드 기준 상대) |

각 레코드의 **마지막 4바이트**가 문자열 포인터이며, 레코드 표 시작 기준 상대 오프셋입니다. `0xFFFFFFFF`는 빈 항목입니다. 문자열은 NUL로 끝납니다.

**LIST** — `u32 n`, `u32 off[n]`(섹션 시작 기준, `off[0] == 4+4n`), 이어서 NUL 문자열들.

**CONT** — `u32 n`, `(u32 off, u32 size)[n]`. 섹션이 오름차순·범위 안일 때만 하위 노드로 재귀합니다.

재구성(`tools/kt_rebuild.py`)은 문자열 풀을 다시 쓰고 포인터를 갱신하며, 컨테이너의 크기·오프셋 필드를 바깥쪽까지 차례로 고칩니다. 일본어 파트 474개 텍스트 항목 전부에서 "그대로 재구성 = 원본과 바이트 동일", "문자열을 늘려도 재파싱 결과 일치"를 확인한 뒤 사용했습니다.

## 문자 인코딩

| 파트 | 인코딩 |
|---|---|
| JPN | CP932(Shift_JIS 확장) |
| CHS | GBK |

일본어 원문에 쓰인 외자(무장 이름의 PUA 문자 등)는 CHS 쪽에서 GBK 사용자 정의 영역에 대응됩니다. 한국어 빌드는 이런 외자를 한글 이름으로 바꾸므로 PUA를 남기지 않습니다. 제어 코드(ESC 시퀀스 `\x1bC#`·`\x1bR`, 서식 토큰 `%s`·`%d`·`%w` 등)는 원문과 같은 순서·개수를 유지해야 하며, [병합 검사](text-build.md)가 이를 확인합니다.
